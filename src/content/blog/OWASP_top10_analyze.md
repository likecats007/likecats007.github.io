## 주제를 고른 이유

최근 수업에서 예외 처리를 배우면서, 예외를 잘못 처리하면 어떤 보안 문제가 생기는지 궁금해졌다. 특히 프로그램이 예상하지 못한 상황에 놓였을 때 오류를 알아채고 안전한 상태로 돌아가는 과정이 궁금해 이 주제를 선택했다.

## A10:2025 부적절한 예외 처리

A10은 OWASP Top 10:2025에서 새로 추가된 범주로, 24개의 CWE를 포함한다. 오류 처리 문제뿐 아니라 논리 오류, 안전하지 않은 실패(failing open) 등 비정상적인 상황을 다루는 과정에서 발생하는 문제를 함께 다룬다. 대표 사례로는 민감한 정보가 포함된 오류 메시지(CWE-209), 처리하지 않은 예외(CWE-248), 예외 발생 뒤 정리 작업 누락(CWE-460), 안전하게 실패하지 않는 문제(CWE-636)가 있다. 이전에 코드 품질 저하라는 넓은 범주에 포함됐던 일부 문제를 더 구체적으로 살펴보도록 분류한 것이다. 

### 무엇이 부적절한 예외 처리인가

예외 상황은 프로그램이 일반적인 흐름대로 동작할 수 없는 예상 밖의 상태를 말한다. 입력값이 빠지거나 잘못된 경우, 메모리나 권한이 부족한 경우, 네트워크 연결이 끊긴 경우 등이 원인이 될 수 있다. 프로그램이 이런 상황을 미리 막지 못하거나, 발생 사실을 알아채지 못하거나, 발생한 뒤 적절히 대응하지 못하면 부적절한 예외 처리가 된다.

예외 처리 문제는 프로그램의 충돌에서 끝나지 않을 수 있다. 오류 메시지로 내부 정보가 노출되거나, 권한 확인이 실패했는데도 작업을 허용하거나, 작업 도중 데이터가 일부만 변경될 수 있다. 그 결과 기밀성·가용성·무결성이 영향을 받을 수 있다. 

### 공격 시나리오

OWASP는 예외 처리 실패가 보안 문제로 이어지는 예시를 세 가지 제시한다.

1. **파일 업로드 중 자원 고갈:** 업로드 처리 중 오류가 발생해도 파일이나 연결 같은 자원을 해제하지 않으면, 실패가 반복될 때 사용 가능한 자원이 고갈되어 서비스 거부로 이어질 수 있다.
2. **오류 메시지를 통한 정보 노출:** 데이터베이스 오류나 상세한 예외 내용이 사용자에게 그대로 보이면, 공격자가 시스템 정보를 파악해 후속 공격을 준비하는 데 이용할 수 있다.
3. **금융 거래의 불완전한 처리:** 출금·입금처럼 여러 단계로 이루어진 작업에서 중간 오류가 났는데 전체 작업을 취소하지 않으면 데이터 상태가 어긋날 수 있다. 재시도나 동시 요청 처리까지 잘못되면 중복 거래 같은 문제로 이어질 수 있다.

이 사례들은 예외 처리가 가용성뿐 아니라 정보 보호와 데이터 상태에도 영향을 줄 수 있음을 보여준다. 

### 대응과 점검 방법

예외가 발생하지 않도록 입력을 검증하고, 요청 횟수나 사용 가능한 자원에 한도를 두는 것이 기본이다. 오류가 발생하면 해당 작업에 필요한 자원을 정리하고, 거래처럼 여러 단계로 이루어진 작업은 중간 단계만 반영되지 않도록 전체를 취소해 일관된 상태를 유지해야 한다. 이를 안전한 실패(failing closed)라고 한다.

사용자에게는 이해하기 쉬운 일반 오류를 보여주고, 스택 트레이스나 내부 경로 등 구현 정보는 응답에 포함하지 않는 편이 안전하다. 조사에 필요한 상세 정보는 서버 로그에 남기되, 비밀번호·토큰 같은 비밀 정보가 기록되지 않도록 해야 한다. 예상하지 못한 예외를 위한 전역 처리기를 두고, 반복되는 오류나 공격 징후를 모니터링해 필요하면 알림이나 제한을 적용할 수 있다.

설계 단계에서는 실패할 수 있는 조건과 복구 방법을 정하고, 코드 리뷰와 정적 분석으로 오류 처리 누락을 살펴봐야 한다. 테스트에서는 잘못되거나 누락된 입력, 네트워크·데이터베이스 오류, 권한 부족 상황을 만들고 자원 정리와 데이터 롤백이 제대로 되는지 확인할 수 있다. OWASP Web Security Testing Guide는 입력 지점과 기대되는 데이터 형식을 파악한 뒤 비정상 입력을 보내고, 응답에 내부 정보가 노출되는지 살펴보는 점검 흐름을 제시한다. OWASP는 위협 모델링, 코드 리뷰, 스트레스·성능·침투 테스트도 대응 방안으로 권고한다. 

## OWASP 지표 읽기


| 지표 | A10 값 | 의미 |
| ----------- | ------- | ----------------------------- |
| 매핑된 CWE 수 | 24 | A10에 연결된 취약점 유형 수 |
| 최대 발생률 | 20.67% | 매핑된 CWE 중 조사 데이터에서 관측된 최대 발생률 |
| 평균 발생률 | 2.95% | 매핑된 CWE의 평균 발생률 |
| 최대 테스트 커버리지 | 100.00% | 개별 CWE에 대한 최대 테스트 커버리지 |
| 평균 테스트 커버리지 | 37.95% | 매핑된 CWE의 평균 테스트 커버리지 |
| 가중 평균 악용도 | 7.11 | 관련 CVE의 공격하기 쉬운 정도를 같은 0~10 기준으로 맞춰 평균한 값 |
| 가중 평균 영향도 | 3.81 | 관련 CVE의 공격 성공 시 영향을 같은 0~10 기준으로 맞춰 평균한 값 |
| 총 발생 건수 | 769,581 | 매핑된 CWE가 확인된 애플리케이션 발생 건수 |
| 총 CVE 수 | 3,416 | 매핑된 CWE와 연결된 CVE 수 |


발생률과 테스트 커버리지는 OWASP에 자료를 제공한 기관들이 테스트한 애플리케이션을 바탕으로 집계된다. 따라서 최대 발생률 20.67%는 모든 웹 서비스에서 이 취약점이 발생할 확률을 뜻하지 않는다. 특정 조사 데이터에서 A10에 매핑된 CWE 중 가장 높게 관측된 발생률로 해석해야 한다. 가중 악용도와 영향도는 매핑된 CVE의 CVSS 점수를 바탕으로 한 값이다. 이 지표는 범주의 배경을 이해하는 데 참고할 수 있지만, 개별 서비스의 위험도는 해당 서비스의 코드와 운영 환경을 따로 점검해야 한다. 

## 정리

A10을 읽으며 예외 처리는 오류 메시지를 출력하는 일에 그치지 않는다는 점을 알 수 있었다. 오류가 생긴 뒤 자원을 정리하고, 데이터 상태를 복구하고, 사용자 응답과 내부 로그를 구분하는 과정까지 포함한다. 예외 상황을 예상하고 안전하게 실패하도록 설계하는 것이 서비스와 데이터의 보안을 지키는 데 중요하다.
